# RFC-0032: TUN direct fallback and DSCP/mark loopback protection

- Number: RFC-0032
- Status: Implemented
- Created: 2026-08-12
- Last updated: 2026-08-13

## background

Healthy routing nft set can only determine whether a healthy overlay currently exists before the
packet enters TUN. The fake IP scenario needs to allow packets with unknown or temporarily lost
health exits to enter TUN, and then Tinect will hand them over to the local default exit for
processing. The previous raw socket fallback bypassed the normal kernel path and is no longer used.

## Goals and Non-goals

The goal is to allow packets such as fake IPs that cannot be filtered by healthy network segments in
advance to continue processing along the native kernel default exit when there is no healthy overlay
candidate, and provide a complete packet mark that can be consumed by policy routing. Non-goals
include modifying existing `nft_healthy_set` rules, providing cross-platform direct fallback,
replacing user-created advanced NAT/routing policies, or allowing fallback packets to bypass the
normal kernel path outside the TUN data plane. When `managed_routes` is turned on, the daemon only
automatically provides basic back-injection masquerade. Users can still configure their own
SNAT/masquerade rules in higher-priority NAT chains and take effect first.

## the term

- marker: configured six-digit DSCP value, used to indicate that the daemon is about to
  back-inject TUN packets.
- Note back: After the daemon reads the packet from the TUN fd, it modifies the marker and writes
  to the same TUN fd again.
- direct fallback mark: optional complete 32-bit packet mark, exclusive to this function.
- fallback zone: non-zero conntrack zone used in the original direction of the back-injection
  packet, exclusively occupied by a Tinect instance.

## design

The top-level `direct` is turned off by default. Configuring `dscp` and non-zero `conntrack_zone`
enables the native egress mechanism. `direct.routes` enables the local machine to be ranked fairly
by priority and overlay. `direct.fallback` (default `false`) only appends the local final candidate
when all matching peer candidates are unavailable; see RFC-0033 for complete ranking semantics. It
only supports Linux, `dscp` must be `0..=63`. The TUN read task is executed on legitimate IPv4/IPv6
packets when the local egress is selected:

1. The configured DSCP marker is first detected; the marker packet is discarded directly to
   prevent incorrect routing from forming a reinjection loop when there is no fwmark. Healthy
   overlay candidates take priority, so if user traffic originally carries marker DSCP and there
   are healthy candidates, it will still go through the overlay instead of being discarded.
2. Parse the conntrack tuple from the complete IP packet and synchronously delete the flow
   established in the default zone 0 through ctnetlink; continue only after receiving a success
   or `ENOENT` confirmation.
3. Leave the ECN bit for IPv4/IPv6 and change DSCP to the configured value.
4. Write the modified complete IP packet back to the same TUN fd, and record the flow for
   cleaning when the overlay is restored.

When the priority is the same, the healthy overlay candidate takes precedence; the explicit direct
route with a higher priority can win. The native direct does not enforce egress ACLs and is not
responsible for source addresses, default routes, or raw sockets; these are handled by the kernel's
normal path. IPv4/IPv6 multicast and IPv4 broadcast targets will not be re-annotated: the link
control packets (MLD/NS, IGMP probes, etc.) generated by the kernel for the TUN interface itself are
not fake-IP traffic. The re-annotation will only mark them again and hand them over to policy
routing, so they will be processed as a normal reject path.

### automatic masquerade

The return packet carries the TUN source address. If it leaves the default exit of the machine
directly, the return packet will not be returned. The initial design requires administrators to
configure NAT themselves; to avoid misuse and reduce configuration burden, when `managed_routes` is
turned on (default) and the `direct` configuration exists, the daemon creates a POSTROUTING nat
chain in a separate `inet` table `tinect_direct_nat_*` via libnftnl/libmnl:

```text
postrouting: type nat hook postrouting priority 150; policy accept
```

priority 150 is located after the regular srcnat (100), so the administrator's own SNAT/masquerade
rules are executed first. Only the back-injection packets that have not been processed and are about
to leave from the non-TUN outbound interface will hit this dumping rule. Matching method: When
non-zero `fwmark` is configured, `meta mark` will be used to accurately match the back-injection
packet; when `fwmark` is not configured or is 0, the TUN address will be used to accurately match
the source address (ordinary underlay traffic will not use the TUN source address).

The same fallback packet will pass through the kernel protocol stack twice with the same tuple
(entering TUN first, and then back-injecting), while the nftables nat chain only performs rule
searches on the first packet of each flow. If you directly reuse the flow established in the default
zone 0 in the first pass, the reinjection packet will skip the masquerade; if you only delete the
flow before reinjection, the old skb may re-publish the old flow when it passes conntrack confirm
later. In order to isolate these two life cycles at the same time, the daemon uses ctnetlink precise
deletion and directional conntrack zone:

```text
prerouting: type filter hook prerouting priority -310; policy accept
  iifname <tun> ip/ip6 dscp <marker> ct original zone set <fallback-zone>
```

Before back-injection, the daemon uses the long-term held `NETLINK_NETFILTER` socket to send
`IPCTNL_MSG_CT_GET`, and queries zone 0 using `CTA_TUPLE_ORIG` and then `CTA_TUPLE_REPLY`. It reads the kernel-assigned
`CTA_ID` for the matching flow and sends `IPCTNL_MSG_CT_DELETE` with the tuple, zone, and ID,
waiting for an ACK. The ID prevents deletion of a replacement flow if the same tuple is reused
between the GET and DELETE requests. `ENOENT` of GET/DELETE is regarded as idempotent success; parsing failure,
socket error, timeout or other kernel rejection will all fail closed: the current packet will not
be returned. Requests are serialized by bounded queues to avoid sudden fallback unbounded occupancy
of memory or netlink sequence space.

The back-injection packet carries the marker and re-enters PREROUTING from the TUN incoming
interface. The raw chain of priority -310 is earlier than conntrack, and its original direction is
assigned to the fallback zone; the reply direction remains zone 0 so that ordinary ingress return
packets can find the connection and perform reverse NAT. In this way, even if the old first-pass skb
confirms the zone 0 flow after deletion, it will not prevent the reinjection flow from executing the
NAT first packet rule in the independent zone; at the same time, the conntrack state semantics of
the first-pass overlay flow will not be changed. `managed_routes: false` still installs zone rules
and runs ctnetlink worker, but does not install automatic masquerade. The administrator's
self-configured SNAT/masquerade can handle the back-injection flow normally.

When the daemon starts and exits normally, execute ctnetlink flush according to the zone to clean up
the crash or fallback flow left over from the last run; when switching back to the healthy overlay
from fallback, the corresponding zone flow is also deleted accurately according to the recorded
tuple. The record collection has a fixed upper limit. When the upper limit is reached, an old item
will be deleted exactly. If the deletion cannot be completed, the new fallback flow will be rejected
to ensure bounded. `conntrack_zone` must be exclusive to this instance and may not be reused
with VRFs, containers, other nftables rules, or other Tinect instances. The nft table is deleted
when rollback and exit are initiated, and the worker flushes the zone when the last holder is
released.

Optional `direct.fwmark` is a full 32-bit packet mark. After configuration, the platform creates a
base chain in a separate `inet` table through libnftnl/libmnl:

```text
prerouting: type filter hook prerouting priority -150; policy accept
```

The chain only matches inbound packets for this TUN. marker DSCP packets set the packet mark, then
clear the DSCP and preserve the ECN. The back-injection packet is a new skb, the mark is always 0,
and the DSCP has been cleared, so the loopback cannot be identified by prerouting alone; loopback
protection is placed on the FORWARD/OUTPUT hooks: any packet carrying this mark and the next hop is
this TUN (whether forwarded or locally generated) will be discarded by its own rules before
re-entering the TUN. Therefore, even if the user mistakenly points the policy routing of the mark
back to TUN, there will be no infinite back-injection. `fwmark: 0` is not accepted because 0 is the
kernel default mark and cannot distinguish between ordinary unmarked packets and direct fallback
injection packets. Tables, chains and rules are submitted by a netlink batch; only Tinect's own
table is deleted when exiting, without using the `nft` command or modifying the user object.

This mark is exclusive to direct fallback and does not support mask; users are not allowed to use
the same mark for normal traffic.

## Security and Compatibility

direct is an explicit opt-in, and the back-injection packet may leave in plain text from the local
default exit without going through the remote ACL. Configuration changes require a reboot.
`nft_healthy_set` still independently maintains the available network segments; the explicit
`direct.routes` prefix will enter the set as an always-available native candidate, and only
`fallback: true` without an explicit route will not expand the set content.

## Migration and deployment

The old raw socket fallback is incompatible and does not require migration; old configuration fields
will continue to be rejected as unknown fields. When deploying, you need to add `direct.dscp` and
instance-exclusive non-zero `direct.conntrack_zone` to the Linux node. When policy routing is
required, add non-zero `fwmark`. Keep `managed_routes` turned on (default) to get automatic
masquerade without manual configuration of basic NAT. The daemon creates its own tables when it
starts, and deletes them when it exits normally and starts a rollback; the administrator only needs
to pre-configure the `ip rule`/route that consumes the mark, and cannot reuse the mark to mark
ordinary traffic. If the administrator needs to customize SNAT/masquerade, placing it in the
postrouting nat chain with a priority lower than 150 can override the automatic rules.

## Test acceptance

- The configuration is turned off by default, verifying DSCP range, non-zero zone, non-zero
  complete u32 mark, Linux-only constraints and `tun.enabled`.
- After IPv4 DSCP is modified, the header checksum is correct, and after IPv6 is modified, ECN is
  retained.
- The marker packet is dropped by the data plane; unknown L4 protocol can still be injected back
  by direct fallback.
- The ctnetlink tuple codec covers IPv4/IPv6, TCP/UDP, ICMP/ICMPv6, IPv6 extension headers, packet
  truncation and fragmentation rejection; GET, ID guarded DELETE, `ENOENT` idempotent and
  timeout/rejection fail closed are all tested.
- netlink batch creates/cleans independent tables, directional zone prerouting chains, DSCP/mark
  rules and mark loop drops.
- POSTROUTING masquerade is automatically installed when `managed_routes` is turned on and cleaned
  up when exiting; it is not installed when `managed_routes: false` is used.
- When `managed_routes: false`, the directional zone is still installed and the ctnetlink worker
  is running. The default exit masquerade configured by the administrator takes effect on the
  back-injection packet (local and forwarding, IPv4/IPv6 verification is passed).
- Privileged fault injection leaves active fallback flow and own nft table with `SIGKILL`. Verify
  that the replacement process flushes the zone before accepting new traffic, rebuilds rather than
  appends nft rules, and restores IPv4/IPv6 fallback; exit normally and verify again that the
  table and zone have been cleaned up. The tuple + zone + ID encoding is covered by the unit test,
  and the duplicate packet is covered by the integrated traffic; `ENOENT` is regarded as
  idempotent success according to the protocol definition. If any other deletion fails, the
  corresponding packet must not be continued to be returned.
- Privileged namespace test verifies IPv4/IPv6 default export, mark policy route, automatic
  masquerade (the peer observes the underlay source address, the return no longer relies on TUN
  source routing, both local and forwarding scenarios), error loopback and resource cleanup.

## Open Questions

none. Configuring hot reloading is not within the scope of this version. Modifying the direct
fallback parameter requires restarting the daemon.

## Implementation Notes

Configuration resolution is at `config`, TUN back-injection and flow bounded records are at
`dataplane`, ctnetlink worker, netlink nft resources (prerouting mark, forward/output loopback
protection, directional zone, POSTROUTING masquerade) and life cycle are at `platform`; the existing
health set update path remains unchanged. Implementation verification covers Linux IPv4/IPv6, local
and forwarding first pass, daemon automatic masquerade, administrator's own masquerade, error mark
loopback, crash replacement and normal exit cleanup; first pass overlay traffic is no longer set to
untracked.
